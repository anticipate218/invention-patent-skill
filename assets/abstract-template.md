# 说明书摘要骨架（发明）

摘要只有 300 字额度，**五要素写全 + 无标题 + 无宣传用语**就算达标。它是技术信息，
**不具有法律效力，也不属于原始记载内容**——不要指望靠摘要救权利要求
（`references/format.md` §5.3）。

配套文件：`assets/patent-outline.md`（整份骨架）、`assets/claims-template.md`（权利要求骨架）。

## 二、五要素核对表

写完逐项打勾。`check_patent.py` 能查字数、标题、宣传用语、附图标记括号，**要素是否写全要靠人看**。

| # | 要素 | 检查问题 | 依据 |
|---|---|---|---|
| 1 | 发明名称 | 与请求书、说明书、权利要求书中的名称**逐字一致**吗？ | 细则第 26 条第 1 款；指南第一部分第一章 4.5.1 |
| 2 | 所属技术领域 | 有一句话点明吗？ | 同上 |
| 3 | 所要解决的技术问题 | 是**客观**表述现有技术缺陷，而不是贬低他人吗？ | 同上 |
| 4 | 技术方案的要点 | 是**以技术方案为主**，而不是只讲效果吗？ | 指南第二部分第二章 2.4（1） |
| 5 | 主要用途 | 有一句话点明吗？ | 细则第 26 条第 1 款 |

## 三、格式红线

| 项 | 要求 | 依据 |
|---|---|---|
| 字数 | **不超过 300 个字（含标点符号）**。超了会被通知删节，或由审查员删节 | 指南第一部分第一章 4.5.1；指南第二部分第二章 2.4 |
| 标题 | 摘要文字部分**不得使用标题**（不要出现「技术领域」「有益效果」这类小标题） | 指南第一部分第一章 4.5.1 |
| 宣传用语 | 不得使用商业性宣传用语 | 细则第 26 条第 1 款；指南第一部分第一章 4.5.1 |
| 引用语 | 不得出现「如权利要求……所述的……」 | 细则第 20 条第 3 款；指南第二部分第二章 2.2 |
| 附图标记 | 出现的附图标记应当**加括号** | 指南第二部分第二章 2.4 末段 |
| 化学式 | 可以包含最能说明发明的化学式 | 细则第 26 条第 2 款 |

> **字数上限的依据容易记错**：300 字来自《专利审查指南》第一部分第一章 4.5.1 与第二部分第二章 2.4，
> **不是**细则第 26 条本身。细则第 26 条只规定摘要应当写明什么。

## 四、❌ / ✅ 对照

| ❌ | 问题 | ✅ |
|---|---|---|
| 本发明结构简单、性能优越，是国内首创…… | 商业性宣传用语；未写技术方案 | 本发明公开了一种……，属于……技术领域。针对……的问题，采用……。本发明用于……。 |
| 分成「技术领域」「有益效果」两小段并加小标题 | 摘要文字部分不得使用标题 | 去掉标题，连成一段 |
| 所述壳体 1 与端盖连接 | 摘要中附图标记未加括号 | 所述壳体（1）与端盖连接 |
| 把整个具体实施方式复制过来 | 远超 300 字 | 压缩到 300 字以内，只留五要素 |
| 如权利要求 1 所述的装置，其壳体为金属 | 说明书/摘要不得用引用语 | 本发明的壳体可以采用金属材料 |

## 五、自检

```bash
python scripts/check_patent.py 我的申请.md --strict
```

脚本会报出摘要的字数、标题、宣传用语与括号问题（`Finding.check = "摘要"`）。
**字数统计会先剥掉 HTML 注释**，所以草稿里留 `<!-- … -->` 提示不会虚增字数。

机械校验不评价合规性；正式提交前由执业代理师复核（见 `SKILL.md`「三条铁律」）。
