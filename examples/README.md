# examples —— 完整范例

本目录只放**完整可跑的申请文件范例**，用来演示「一份合格的发明专利申请文件长什么样」，以及各脚本实际会给出什么输出。

| 文件 | 内容 |
| --- | --- |
| `draft-example.md` | 一份完整的发明专利申请文件范例（摘要 + 权利要求书 + 说明书 + 说明书附图说明），可直接喂给 `scripts/check_patent.py` |
| `disclosure-example.md` | 同一件发明的**技术交底书**范例，可直接喂给 `scripts/gen_draft.py` 一键出稿 |
| `README.md` | 本文件：范例的读法、验证命令、输出含义、以及**不要照抄**的地方 |

---

## 一、范例是什么

`draft-example.md` 是一件虚构的发明：

> **一种传送带异物视觉检测方法**

它是一件**方法**发明，包含：图像采集单元、传送带、速度编码器、光照度传感器等部件，以及逐帧亮度差筛选候选区域、局部纹理梯度比对确认为异物、按编码器脉冲当量换算位置并输出剔除信号等步骤。

选这个题材的原因是它同时覆盖了本技能要检查的几类东西：

- **方法权项**：独权写步骤流程，从权逐层加限定（阈值设置、纹理计算方式、标定方式、校正方式）。
- **装置部件 + 附图标记**：正文里出现 `传送带 1`、`图像采集单元 2`、`速度编码器 3`、`候选区域 6`、`异物区域 7`、`光照度传感器 8` 等标记，可以验证「标记双向一致」。
- **多项从属权利要求**：第 7 项为「根据权利要求 4 或 5 所述的……」，且它引用的两项都是**普通从属**（不是多项从属），因此不违反细则第 25 条第 2 款。
- **算法类特征**：涉及图像处理步骤，可对照客体审查（专利法第 25 条 / 指南第二部分第九章）的写法边界。

范例共有 **7 项权利要求**（1 项独立权利要求 + 6 项从属权利要求），说明书含全部五个小节，**摘要 184 字**。

## 二、怎么读

按这个顺序看，收益最大：

1. **先看摘要**（文件开头）：注意它只写了「领域 → 要解决的问题 → 技术方案要点 → 用途」，**没有标题、没有「本发明克服了……缺点」这类宣传语、没有引用文献**。
2. **再看权利要求书**：注意第 1 项（独权）是「前序部分 + 特征部分」结构，用「其特征在于」分隔；从权一律以「根据权利要求 N 所述的……」开头，并回指「所述……」的技术特征。
3. **再看说明书**：
   - `技术领域` —— 一句话，不展开。
   - `背景技术` —— 只陈述现有技术及其不足，**不贬低具体产品或厂商**；引证文件单独放。
   - `发明内容` —— 与独权对应地写「要解决的技术问题 / 技术方案 / 有益效果」。
   - `附图说明` —— 逐图一句话说明「图 1 是……示意图」，此处列举标记**不加括号**。
   - `具体实施方式` —— 至少一个完整实施例，**附图标记放在技术名称后面且不加括号**（如「图像采集单元 2 位于传送带 1 上方」）。
4. **最后自己跑一遍脚本**（见下节），把范例当「满分答案」来校准你的直觉。

## 三、验证命令

在**技能根目录**执行（Windows 下把 `python` 换成你的解释器路径亦可）：

```bash
python scripts/check_patent.py examples/draft-example.md --strict
```

预期结果：**退出码 0**，并打印

```
没有发现问题。
结论：机械校验全部通过。
```

其中会报告：发明名称「一种传送带异物视觉检测方法」、权利要求 7 项、说明书小节顺序为 `技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式`、摘要字数 184。

想换成机器可读格式，加 `--json`：

```bash
python scripts/check_patent.py examples/draft-example.md --json
```

把**交底书范例**一键转成草稿，再出整包投稿文件：

```bash
python scripts/gen_draft.py examples/disclosure-example.md -o 我的申请.md --strict
python scripts/build_all.py 我的申请.md -o 输出目录 --pdf
```

`--strict` 表示「需要复核」的项也当失败——交底书里没给的字段会被留成显式缺口（`（请补：…）`）而不是编一个，所以缺东西时它会直接失败给你看。

## 四、输出怎么理解

`check_patent.py` 一共跑 **9 类机械检查**：部件齐全、发明名称、说明书结构、摘要、权利要求、附图标记、措辞、序列表、附图。每条问题都带一个 `basis` 字段，指向 `references/` 里对应的规范小节（例如 `references/claims.md §5`），你要判断「这条到底算不算问题」时就去读那个小节。

三类结果的含义：

| 结果 | 含义 | 你要做什么 |
| --- | --- | --- |
| **错误** | 明确违反形式要求（如摘要超 300 字、两项多项从属互相引用） | 必须改，否则会被补正 |
| **警告** | 疑似问题，需要人判断（如「约」「左右」这类不清楚措辞、附图标记列了但正文没用到） | 逐条确认；确属正当用途可保留 |
| **通过** | 未发现形式缺陷 | 不代表实体上没问题，见下 |

## 五、⚠️ 范例**不能**当模板照抄的部分

- **技术内容是虚构的**，参数（3×3 邻域、16×16 图像块、3 倍均值等）只是为了让文字自洽，**没有经过任何实验验证**。你自己的申请必须写你真实做出并验证过的技术方案。
- **不是真实申请文件**，没有经过任何代理师或审查员核查，也**未做过新颖性/创造性检索**。范例通过机械校验，只说明其**形式**合规。
- **`draft-example.md` 是撰写加工后的成品形态，不是交底书。** 同一件发明的**交底书形态**放在 `disclosure-example.md`：从那份开始才能看到「原始素材 → 成品」之间被补了什么、被规范了什么。你手上只有技术交底材料时，先走 `references/drafting-playbook.md` 的流程，或用 `scripts/gen_draft.py` 出一版草稿再逐条补。
- **正文标记不带括号，权利要求标记带括号**——这两处写法不同是**故意的**，不是笔误。规则差异见 `references/drawings.md` §2.1。
- 范例没有涉及：序列表（无氨基酸/核苷酸序列）、彩色附图或照片、PCT/优先权、以及审查意见答复。这些情形请查 `references/specification.md`、`references/drawings.md`、`references/procedure.md`、`references/prosecution.md`。

## 六、交底书范例：从原始素材到成品

`disclosure-example.md` 是**同一件发明**的技术交底书，用 `##` 分节（发明名称 / 技术领域 / 背景技术 / 技术问题 / 独权前序 / 必要技术特征 / 特征部分引导语 / 附加技术特征 / 有益效果 / 附图 / 附图标记 / 实施例 / 摘要）。它的价值在于**对照**：

- 交底书写「必要技术特征」时用的是技术人员的话，成品里的独权要变成规范的「前序部分 + 特征部分」；
- 交底书里的附图标记可能只给了编号，成品必须给每个标记配名称、并保证双向一致；
- 交底书没有的东西（这里刻意留了几处），`gen_draft.py` **不会替你编**，而是在草稿里留下 `（请补：…）` 并在报告里逐条列出。

所以这份交底书同时也是「生成器不会编技术内容」这一承诺的**活体证据**：跑一遍，看它把哪些洞报了出来。

## 七、想再要更多范例？

本目录刻意只保留**一件**发明（交底书形态 + 成品形态各一份），避免维护出互相矛盾的「参考答案」。

需要别的题材时，用骨架先搭结构再填内容：

```bash
python scripts/check_patent.py --init 我的申请.md
python scripts/check_patent.py 我的申请.md --strict
```

`--init` 生成的是**空骨架**（只有章节标题和填写提示），提示以 HTML 注释形式给出，脚本计数时会自动剥离，所以骨架本身也能直接通过校验。可复用的片段另见 `assets/patent-outline.md`（整体骨架）、`assets/claims-template.md`（权利要求书）、`assets/abstract-template.md`（摘要）。
