# 从交底书到申请文件：实操手册

这份文档回答"**动手时按什么顺序做、每一步产出什么、缺信息时问什么**"。
规则与法条见 `references/format.md`、`references/claims.md`、`references/specification.md`、`references/drawings.md`；授权条件与答复见 `references/examination.md`、`references/prosecution.md`。

---

## §1 全流程总览

| 步骤 | 做什么 | 产出物 |
|---|---|---|
| 0 | 判断**该不该申请、申请什么类型**（发明／实用新型／外观） | 类型结论 + 公开时机 |
| 1 | 收技术交底书，把缺失信息问出来 | 补齐的交底书（§2） |
| 2 | 提炼发明点：技术问题 → 技术手段 → 技术效果 | 发明点清单（§3） |
| 3 | 检索现有技术 | 最接近现有技术 + 区别特征初判（§4） |
| 4 | 权利要求布局：独权 + 从权层次 | 权利要求书草稿（§5） |
| 5 | 写说明书：三要素 + 实施例 + 变型 | 说明书草稿（§6） |
| 6 | 形式自检 | `check_patent.py --strict` 0 失败 |
| 7 | 出 Word/PDF，提交 | 申请文件（`references/templates.md`） |

**两条贯穿全程的原则**：

1. **申请文件一旦提交，后续修改不得超出其记载的范围**（《专利法》第 33 条）。所以"先交上去再说"是错的——**提交时写进去的东西，就是你能用的全部弹药**。实施例与变型宁可多写。
2. **公开是不可逆的**。论文发表、产品上市、样机演示都可能破坏自己申请的新颖性。**先申请，后公开**；需要展示的先签保密协议。公开时机请与代理师确认。

## §2 技术交底书：应当包含什么、缺了问什么

### 2.1 一份能用的交底书

| 项 | 内容 |
|---|---|
| 1 | 技术领域（一句话） |
| 2 | 现有技术怎么做（结构/流程），最好给出具体的对比对象 |
| 3 | 现有技术的**客观缺陷**（对应"技术问题"） |
| 4 | 本发明**要解决的技术问题** |
| 5 | 本发明的**技术方案**：由哪些部件/步骤构成，连接关系或先后顺序如何 |
| 6 | **关键参数**：范围、典型值、为什么取这个范围 |
| 7 | **实施例**：至少一个能跑通的完整方案 |
| 8 | **替代方案**：可以换成什么材料/部件/顺序/算法 |
| 9 | **效果数据**：与对比对象相比，指标改善了多少，在什么条件下测的 |
| 10 | **公开情况**：是否已发表论文、参展、销售、演示；有无优先权基础 |
| 11 | 发明人与申请人信息、是否职务发明 |

### 2.2 交底书信息缺失时的追问清单（可直接照抄）

> 以下问题请按顺序确认，**第 1～4 题不回答清楚，权利要求就没法写**。

1. **现有技术里最接近的是哪一个？** 有具体产品、文献或专利吗？（只给"市面上都这样"无法定位区别特征）
2. **相比它，你的方案改了哪几处？每处改动的目的是什么？**（这是区别技术特征的来源）
3. **这些改动分别带来了什么可测量的效果？** 有对比数据吗？（没有数据时，效果只能定性描述，创造性论证会困难得多）
4. **哪些细节是"必须这么干"、哪些是"可以换别的"？**（必须的进独权，可以换的进从权与变型）
5. 有没有**具体的数值范围**？端点和中间值分别是多少？为什么取这个范围？
6. 有没有**替代材料/部件/步骤/参数区间**？
7. 方案在**什么条件下会失效**？边界在哪里？（写进说明书能防止别人绕开，也能避免概括过宽）
8. 是否已经**对外公开**过（论文、展会、销售、客户演示）？日期是哪天？
9. 是否要**向外国申请**？（涉及保密审查）
10. 有没有**已经知道的近似专利**？

**引导话术示例**：

> "您说的'检测更准'，能不能给一个具体场景？比如传送带速度多少、异物多大、原来漏检多少、现在漏检多少——有这个数字，权利要求里就能写'在……条件下漏检率低于……'，否则审查员会认为效果无法确认。"

## §3 发明点提炼

### 3.1 因果链：问题 → 手段 → 效果

每个发明点都要能读成一句话：

> **为了解决【背景技术中的什么缺陷】，采用【什么技术手段】，从而【带来什么技术效果】。**

三者必须一一咬合：

- 效果对不上问题的 → 是"顺带的好处"，不能用来支撑创造性；
- 手段对不上效果的 → 说明手段与效果之间没有因果关系，写了也没用；
- 问题在背景技术里没铺垫 → 审查员会认为技术问题是被临时构造出来的。

### 3.2 把一个改进拆成多个可主张的发明点

同一个产品改进，往往能拆成若干独立的技术贡献（例如：**结构改动**、**控制策略改动**、**数据处理方式改动**）。拆开的好处：

- 独权可以聚焦在最强的那一个上，其余作为从权或另案；
- 答复审查意见时有腾挪空间（某一个特征被对比文件公开时，还有其他区别特征可用）。

### 3.3 不值得申请的情形（先劝阻，别硬写）

- 纯粹的**智力活动的规则和方法**（《专利法》第 25 条第 1 款第（二）项）——例如单纯的算法本身、比赛规则、教学方法；但**算法与具体技术领域结合、解决技术问题并产生技术效果**的方案可以申请，写法见 `references/examination.md` §6。
- 纯粹的**商业规则、管理方法、信息呈现方式**（同上，未与技术手段结合）。
- 已被公开且无改进空间、或改进是**本领域公知常识的简单替换**。
- 属于《专利法》第 5 条、第 25 条排除的其他客体（见 `references/examination.md` §5）。
- 只靠**保密**更有利的技术（如工艺配方），申请人自己权衡。

## §4 检索

### 4.1 去哪检

官方与常用入口见 `references/sources.md` §2。至少做**关键词 + 分类号**两路检索。

### 4.2 构造检索式

1. 把方案拆成**技术特征词**：对象词（传送带、周转箱）、动作词（检测、折叠）、效果词（异物识别）。
2. 找出**同义词与上下位词**：异物／杂质／掺杂；相机／摄像／图像采集。
3. 用 **IPC/CPC 分类号**缩小范围（分类号由技术领域决定，比关键词稳定）。
4. 检索式示例：`(传送带 OR 皮带) AND (异物 OR 杂质) AND (图像 OR 视觉 OR 相机)`。

### 4.3 读对比文件（重点是"它没公开什么"）

对每个接近的文献，记三件事：

| 问题 | 记录 |
|---|---|
| 它公开了本方案的哪些特征？ | 逐条列，**具体到段落/权项号** |
| 它**没**公开哪些特征？ | 这就是你的**区别技术特征** |
| 该区别特征在本方案中起什么作用？ | 这就是"**实际解决的技术问题**"的依据 |

> 这一步的产出直接决定创造性怎么答。**三步法**的完整写法见 `references/examination.md` §3，答复中的套用见 `references/prosecution.md` §4。

## §5 权利要求布局

### 5.1 独立权利要求写多少特征

- **必要技术特征一个不能少**：少了就解决不了技术问题（《专利法实施细则》第 23 条第 2 款）。
- **非必要技术特征一个不要多**：多写一个，保护范围就窄一圈，而且日后**很难通过修改删掉**——答复阶段主动删除独权中的技术特征从而扩大保护范围，属于**不予接受的修改**（见 `references/prosecution.md` §3）。
- 判断标准：**没有它，还能不能解决那个技术问题？** 能，就不要写进独权。

### 5.2 从属权利要求怎么分层

从权的作用是**给它加保险**：独权被无效或被认为缺乏创造性时，退到从权仍然有范围。

分层建议（按优先级）：

1. 独权的**下位具体化**（具体结构/具体算法/具体判据）；
2. **关键参数范围**（端点值 + 中间值各写一项）；
3. **材料/部件/型号的选择**；
4. **方法与装置的配合**（如果独权是装置，从权可写其控制方法特征）；
5. **应用场景/用途限定**（放在最后）。

### 5.3 多项从属：省钱但有限制

- 多项从属能一次引用多项，减少权项数、降低费用；
- 但**只能以择一方式引用在前的权利要求，且不得作为另一项多项从属的基础**（《专利法实施细则》第 25 条第 2 款）；
- 实务上，**别把所有从权都写成多项从属**——引用关系一乱，就容易被形式缺陷缠住。

### 5.4 保护主题怎么选

| 方案类型 | 建议 |
|---|---|
| 产品改进（结构/材料） | 至少一项**产品**权项；有控制逻辑的再加**方法**权项 |
| 方法/工艺改进 | **方法**权项；能落到设备的再加**装置**权项（覆盖实施该方法的设备） |
| 算法/AI 改进 | 必须写成"**技术方案**"：算法与具体技术领域结合、有技术手段与技术效果（见 `references/examination.md` §6）；常见组合是"方法 + 装置 + 存储介质 + 设备"四件套 |
| 用途 | **用途**权项单独写，不要与产品权项混在同一主题名称里 |

> 同一件申请里写"产品 + 方法"是常见的；但注意**单一性**要求（《专利法》第 31 条第 1 款），它们必须属于**一个总的发明构思**。

### 5.5 单件申请还是分案

- 一个总的发明构思下的多项发明，可以合在一件申请里；
- 若审查中认为缺乏单一性，可以**分案**；分案的时机与期限见 `references/procedure.md` §4。

## §6 说明书撰写策略

### 6.1 实施例写几个

- **至少一个完整、能重复实现的实施例**（《专利法》第 26 条第 3 款的"能够实现"）。
- 技术方案概括得越宽，需要的实施例越多。别用"一个实施例"去支撑"所有高分子材料"这类概括——那会落入"得不到说明书支持"。
- 参数范围要写**端点 + 至少一个中间值 + 取值范围的理由**。

### 6.2 上位概括：既要宽，又不能超范围

- 概括的上位概念必须在说明书中**已经记载了多个下位实现**，且本领域技术人员能预期上位概念下的其他实现也能达到同样效果。
- 纯功能性限定（"实现××功能的模块"）风险高：**产品权利要求应尽量避免功能或效果特征**，除非该功能特征在说明书中已由具体结构/步骤支撑。
- 概括的边界：**修改不得超出原说明书和权利要求书记载的范围**（《专利法》第 33 条）——想以后能用，就得现在写进去。

### 6.3 怎么写变型与替代方案

- 用"在另一实施例中，所述 X 可以替换为 Y"的句式，明确给出**可替换项**；
- 给**参数区间**时要说明区间外为何不行（这就是日后答复"概括过宽"的论据）；
- 把"失效边界"写清楚（§2 第 7 问）。

### 6.4 实验数据怎么摆

- 数据要**成表**，含对比对象、测试条件、指标；
- 数据要在**说明书**里（摘要与意见陈述都不算原始记载）；
- 数据要能落到"有益效果"那一段上去，一一对应。

### 6.5 附图怎么配合

- 结构类方案至少给一幅**整体结构示意图**（通常选作摘要附图）与必要的**局部放大/剖面图**；
- 方法类方案给**流程图**；
- 标记在"说明书附图"与正文之间**双向一致**（见 `references/drawings.md` §2、§3）。

## §7 常见误区

| 误区 | 后果 |
|---|---|
| 把说明书当论文写（大段背景综述、致谢、个人心得） | 篇幅浪费，关键内容反而没写；可能夹带宣传用语 |
| 效果写成口号（"效果显著""填补空白"） | 违反《专利法实施细则》第 20 条第 3 款；创造性论证无据 |
| 独权塞入非必要技术特征 | 保护范围白白缩小，且日后难以删除 |
| 从权只是重复独权 | 起不到"保险"作用，还可能被指保护范围实质相同 |
| 只写一个点、概括到整个类 | 得不到说明书支持（《专利法》第 26 条第 4 款） |
| 关键限定只写在摘要里 | 摘要**不属于原始记载内容**，不能作为修改依据 |
| 交底书里的"可替换方案"没写进说明书 | 答复审查意见时无兵可用（修改不得超范围） |
| 先发论文/先参展再申请 | 自己的公开成为现有技术，破坏新颖性 |
| 把保密配方原样写进申请文件 | 一旦提交即可能被公布，**公开不可逆** |
| 未经核实就引用法条条号 | 现行细则是 2023 年修订版，条号与旧版不同（见 `references/sources.md` §1） |
| 认为"脚本通过 = 能授权" | 脚本只做形式校验；实体判断必须由执业代理师完成 |

## §8 与用户协作的分工

**你（助手）可以做的**：把交底书整理成规范文本、提炼三项因果链、按规则搭出权利要求与说明书骨架、跑机械自检、把形式缺陷一次清干净、解释法条与流程。

**必须由执业专利代理师拍板的**：

- 最接近现有技术的选择、区别技术特征的认定、创造性的结论；
- 权利要求的保护范围是否恰当（要不要放弃某个特征、要不要分案）；
- 审查意见答复中的修改是否超范围、是否符合"针对通知书指出的缺陷"的限制；
- 公开时机、是否需要保密审查、是否向外国申请；
- 任何涉及权利丧失风险的程序性决定（期限、恢复、复审）。

**对用户的提示语**（建议照此说）：

> 我已经把申请文件按形式要求整理好，并跑通了机械自检（0 失败）。但**新颖性、创造性和保护范围需要由执业专利代理师结合检索结果判断**，本工具的检查结果不能替代法律意见。
