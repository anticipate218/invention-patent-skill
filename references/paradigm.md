# 通用生成范式：从任意技术交底到发明专利申请文件

本文是本技能的“生成引擎”层：不绑定机械、电子、通信、软件算法、化学材料、生物医药等任何单一领域，只规定每一层的输入、产物、通过门槛和上下层关系。

> **领域无关不等于不需要领域知识。** 范式负责把信息组织成稳定结构；技术事实、实验数据和可实现细节仍必须来自发明人、技术交底书或经过确认的资料，不得由助手补造。

## §1 一句话模型

一份发明专利申请可以抽象为：

> **一个明确的技术问题** + **为解决该问题而共同作用的一组技术特征** + **足以让本领域技术人员实现该方案的公开**。

这三部分分别决定：为什么要做、保护什么、凭什么能够获得并维持该保护。任何一部分为空，后面的权利要求、说明书和答复都会失去稳定基础。

## §2 七层流水线

| 层 | 输入 | 必须产出 | 通过门槛 |
|---|---|---|---|
| 0. 事实层 | 交底书、访谈记录、图纸、实验记录 | 事实清单、推测清单、未知清单 | 事实与猜测已分开；未知项没有被自动补齐 |
| 1. 发明点层 | 已确认事实、现有方案及其不足 | “技术问题—区别特征—技术效果”三元组 | 每个效果都能回指到具体特征或特征组合 |
| 2. 技术模型层 | 发明点三元组 | 对象、动作、关系、参数和术语表 | 同一部件/步骤只有一个主名称；关系足以复原方案 |
| 3. 权利层 | 技术模型、检索与布局信息 | 独立权利要求、从属权利要求树、退守层级 | 独权含解决问题所需的必要特征；从权逐层增加限定 |
| 4. 支撑层 | 权项树、原始技术事实 | 说明书五部分、实施例、效果依据 | 权项中的每个特征均有说明书依据；方案能够实现 |
| 5. 公开层 | 说明书、权项、图纸 | 摘要、摘要附图、附图说明、标记表 | 术语和标记双向一致；摘要忠实且不扩大原始记载 |
| 6. 交付层 | 全套申请文件 | 自检报告、待确认清单、Markdown/Word/PDF | 机械检查通过；未确认事项显式保留；人工复核完成 |

七层不是七份互不相关的文档，而是一条单向生成、双向校验的链：后一层只能使用前一层已经确认的内容；发现问题时必须回到产生该内容的最早一层修正。

## §3 第 0 层：事实层

### 3.1 三栏事实表

先把交底材料拆成三栏：

| 类别 | 可以写什么 | 处理方式 |
|---|---|---|
| 已确认事实 | 已存在的结构、步骤、连接关系、参数范围、测试结果 | 可以进入权项和说明书 |
| 技术推测 | “通常可以”“理论上可能”“预计能够”等未经确认内容 | 只能进入待确认清单，不得伪装成实施例 |
| 未知信息 | 缺失的尺寸、顺序、条件、输入输出、替代方案 | 向发明人提问；无法确认时明确留空 |

### 3.2 最小提问集

至少确认：

1. 现有方案是什么，具体缺陷在什么条件下出现？
2. 本方案增加、删除或改变了哪些结构、步骤或关系？
3. 哪些特征缺一不可，哪些只是优选方案？
4. 每个声称的效果由哪些特征共同产生？
5. 是否有图纸、流程图、实验或对比数据支持？
6. 是否存在尚未公开、尚未验证或不准备公开的内容？

### 3.3 禁止跨层补造

不能因为“本领域通常如此”就在事实层加入用户没有提供的传感器、阈值、材料、算法、实验结果或尺寸。常规知识可以用来提出问题，不能直接变成申请人的技术事实。

## §4 第 1 层：发明点层

### 4.1 发明点三元组

每个候选发明点都写成：

- **技术问题**：在什么对象、工况或流程中，现有方案具体哪里不够；
- **区别特征**：本方案相对现有方案改变了什么，以及这些特征如何配合；
- **技术效果**：由上述区别特征直接带来的、可以解释或验证的效果。

不要把“成本更低、体验更好、更加智能”单独当作技术效果。必须继续追问：由什么技术手段降低了哪一类资源消耗、误差、时延、故障或操作量。

### 4.2 因果链门槛

合格链条应当能读成：

> 因为采用【特征 A + 特征 B 的关系】，所以改变了【物理过程、信息处理过程或控制过程】，进而获得【可说明的技术效果】。

如果效果无法回指到特征，效果可能是宣传语；如果特征无法回指到技术问题，特征可能只是无意义堆砌。

## §5 第 2 层：技术模型层

### 5.1 五类词表

| 类别 | 作用 | 示例形式 |
|---|---|---|
| 对象词 | 定义部件、材料、数据对象、工序对象 | 第一模块、反应物、待处理数据 |
| 动作词 | 定义步骤或功能行为 | 获取、比较、加热、传输、校正 |
| 关系词 | 定义空间、连接、时序、控制或数据关系 | 固定于、连通、早于、响应于、映射到 |
| 参数词 | 定义可测量或可判断的边界 | 温度范围、采样周期、浓度、误差阈值 |
| 效果词 | 记录技术结果，不直接代替技术特征 | 降低时延、提高稳定性、减少副反应 |

### 5.2 术语归一

同一对象在全文只保留一个主名称，同义词和上位词用于检索或备选布局，不在权利要求中随意轮换。第一次出现给出完整名称，后续回指保持一致。

### 5.3 关系优先

专利保护的往往不是“有什么”，而是“它们如何共同作用”。技术模型必须记录连接、位置、先后、输入输出、控制与约束关系；只列零件或步骤名称不能恢复技术方案。

## §6 第 3 层：权利层

### 6.1 独立权利要求

独权使用“最小必要特征集”：删除任何一个特征都会使所述技术问题无法按原方案解决。不能把实施例中的所有细节都塞入独权，也不能只写目标或结果而缺少实现该结果的技术手段。

常用的领域无关骨架：

- **产品/装置**：一种【主题】，包括【部件 A】和【部件 B】，其中【A、B 的结构/连接/控制关系】；
- **方法/工艺**：一种【主题】方法，包括：获取【输入】；依据【规则或处理】得到【中间结果】；基于【中间结果】执行【输出动作】；
- **系统**：一种【主题】系统，包括【多个功能实体】，各实体通过【数据/信号/物理关系】共同完成【技术过程】；
- **软件/算法方案**：把算法特征与具体技术问题、技术数据、处理过程和技术效果绑定，不写成脱离技术场景的抽象规则（指南第二部分第九章 6.1.2～6.1.4、6.3.1～6.3.2）。

具体格式、前序与特征部分以及引用规则见 `references/claims.md`。

### 6.2 从属权利要求树

从权不是随机增加细节，而是按退守价值分层：

1. 核心关系的进一步限定；
2. 可替代结构、步骤或材料；
3. 参数范围与工况；
4. 控制、校准、异常处理或容错；
5. 便于后续并入独权的高价值组合。

每项从权都应回答：“如果独权被现有技术击中，这项新增限定为什么仍值得保留？”

### 6.3 权利层门槛

- 独权中的每个特征都来自事实层和技术模型；
- 每个必要特征均在说明书中有明确支撑；
- 从权只引用在前权项，多项从属遵守细则第 25 条第 2 款；
- 术语清楚、简要，不使用“如图所示”“最好”“等等”等不清楚写法；
- 权项树同时覆盖合理宽度与可退守层级。

## §7 第 4 层：支撑层

说明书按法定顺序写成技术领域、背景技术、发明内容、附图说明、具体实施方式（细则第 20 条第 1、2 款）。生成时按以下依赖关系组织：

| 部分 | 从哪一层生成 | 必须完成的任务 |
|---|---|---|
| 技术领域 | 主题与对象词 | 用一句话定位，不提前写效果 |
| 背景技术 | 事实层与技术问题 | 客观说明现有方案和具体不足 |
| 发明内容 | 发明点与独权 | 技术问题、技术方案、有益效果互相对应 |
| 附图说明 | 图纸与标记表 | 逐图说明，不借附图补造技术内容 |
| 具体实施方式 | 全部已确认事实 | 写清结构、步骤、关系、条件与至少一种实现方式 |

软件或 AI 方案还应写清模型/算法与具体技术领域的结合、必要输入输出和共同产生技术效果的机制；涉及模型构建或训练时，按指南第二部分第九章 6.3.1 核对必要模块、层级、连接关系、步骤与参数。

说明书的通过门槛不是“写得长”，而是本领域技术人员能够依据其内容实现方案（专利法第 26 条第 3 款），且权利要求能够以说明书为依据（第 26 条第 4 款）。

## §8 第 5 层：公开层

### 8.1 摘要

摘要从已经完成的说明书压缩得到，不得反过来成为新增技术特征的来源。写明技术领域、技术问题、主要技术方案和主要用途，不超过 300 字；详细规则见 `references/format.md` §5。

### 8.2 附图与标记

先生成“技术名称—标记—出现位置”三列表，再写附图说明和正文。正文、权利要求、摘要和附图说明中的括号规则不同，必须分别处理，见 `references/drawings.md` §2.1。

### 8.3 一致性门槛

- 名称、术语、步骤编号和附图标记全文一致；
- 权项出现的特征能在说明书定位；
- 说明书声称的效果能回指到技术方案；
- 图中标记与文字说明双向对应；
- 摘要没有加入说明书未记载的新内容。

## §9 第 6 层：交付层

交付物至少包括：

1. 完整申请文件草稿；
2. 权项树或权利要求布局说明；
3. 待确认清单；
4. 机械自检报告；
5. 如需正式版式，再生成 Word 或 LaTeX/PDF。

推荐命令：

```bash
python scripts/check_patent.py 我的申请.md --strict
python scripts/make_docx.py 我的申请.md -o 我的申请.docx
python scripts/check_latex.py --require
```

机械校验只检查可以形式化的规则，不评价新颖性、创造性、保护范围或最终授权可能性。

## §10 领域适配矩阵

通用流水线不变，变化的是事实层要收集的内容和专项审查依据：

| 领域 | 事实层重点 | 权项与说明书重点 | 专项入口 |
|---|---|---|---|
| 机械/结构 | 部件、连接、位置、运动与受力关系 | 结构关系和工作过程，附图标记一致 | 指南第二部分第二章；`references/drawings.md` |
| 电子/控制/通信 | 信号来源、接口、时序、状态与控制关系 | 输入输出、信号链、触发条件、协同关系 | 指南第二部分第二章、第四章 |
| 软件/AI/数据处理 | 技术数据含义、算法输入输出、运行环境 | 技术问题—算法特征—技术效果的整体关系 | 指南第二部分第九章；`references/examination.md` §6 |
| 化学/材料 | 组成、制备条件、范围、测试方法与对比数据 | 组分关系、工艺条件、效果与可实施性 | 指南第二部分第十章 |
| 中药 | 原料、制备、用途、验证资料 | 专项公开与效果依据 | 指南第二部分第十一章 |
| 生物/序列 | 序列、来源、功能、实验条件与结果 | 充分公开；需要时单独提交序列表 | 细则第 20 条第 4 款 |
| 工艺/方法 | 初始条件、步骤顺序、参数、终止条件 | 步骤间因果和时序关系 | `references/claims.md`、`references/specification.md` |

使用专项章节前应核对 CNIPA 当前公布版本；本文只做路由，不替代各领域的审查细则。

## §11 双向回归规则

生成不是一次从上到下写完，而是持续回归：

- 权项缺少支撑 → 回到事实层或支撑层，不在权项中凭空补特征；
- 实施例无法实现 → 回到技术模型和事实层补问；
- 摘要出现新特征 → 删除或先确认说明书原始记载；
- 检索发现独权过宽 → 重做发明点三元组和权项树；
- 审查意见要求修改 → 只能在原说明书和权利要求书记载范围内退守（专利法第 33 条）。

## §12 范式级反面模式

出现下列情况，说明流水线被破坏：

- 先写一篇“看起来像专利”的长文，再倒推发明点；
- 把未知信息自动补成“常规参数”或实验结果；
- 独权只写目标、用途或效果，没有实现关系；
- 说明书与权项分别生成，术语和范围互不对应；
- 用摘要、附图或后补材料为原申请增加新内容；
- 所有领域套同一份句子模板，却没有进入专项审查入口；
- 把机械自检通过解释为可以授权。

## §13 最终检查表

- [ ] 事实、推测、未知已经分开
- [ ] 至少形成一个完整的“问题—特征—效果”三元组
- [ ] 技术模型包含对象、动作、关系和必要参数
- [ ] 独权是最小必要特征集，不是实施例细节总和
- [ ] 从权形成有价值的退守层级
- [ ] 权项特征均有说明书依据
- [ ] 说明书足以使本领域技术人员实现
- [ ] 摘要和附图没有新增技术内容
- [ ] 专项领域规则已经路由并核对
- [ ] 待确认事项没有被悄悄写成事实
- [ ] 已运行机械自检并安排专业复核

## §14 待核实项

本范式刻意不写各技术领域的全部专项数字、实验要求和判断阈值。遇到下列事项时，应回到 CNIPA 最新原文或交由具有相应技术背景的代理师核对：

1. 化学、材料、中药、生物领域的专项公开与实验数据要求；
2. 计算机程序、人工智能与商业规则交叉方案的最新审查口径；
3. 涉及诊断治疗方法、遗传资源、伦理或个人信息的客体与合规问题；
4. 个案是否具备新颖性、创造性、实用性和充分公开；
5. 境外申请、保密审查、优先权与期限的个案适用。

本文件是生成与校验范式，不是法律意见，也不替代执业专利代理师。
