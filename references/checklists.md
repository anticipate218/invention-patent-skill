# 提交前自检清单

**用法**：先跑机械检查，再人工逐项过清单。

```bash
python scripts/check_patent.py 我的申请.md --strict      # 形式与结构：0 失败 0 警告
python scripts/make_docx.py 我的申请.md                  # 生成 Word（可选）
python scripts/check_latex.py --require                  # 用 LaTeX 模板时：真编译 + 结构核对
python scripts/validate_skill.py --strict                # 只在你改本技能自身时用
```

> 🔴 = 高危项：不满足可能直接造成形式缺陷、权利丧失或无法补救的后果，请优先确认。
> 脚本只做**机械校验**，不评价新颖性、创造性和保护范围；**实体判断请交给执业专利代理师**（见 `references/sources.md` §4）。

---

## §1 发明名称与申请文件组成

- [ ] 🔴 申请文件齐全：**请求书、说明书摘要、权利要求书、说明书**（必要时附图）——缺件不能获得申请日
- [ ] 发明名称一般不超过 **25 字**，必要时不超过 **60 字**
- [ ] 名称与**请求书**中的名称一致
- [ ] 名称不含人名、地名、商标、型号、商品名称、商业性宣传用语
- [ ] 名称能体现**申请类型**（产品／方法／用途），不用"一种……技术"这类不清楚的表述
- [ ] 有附图的，已在**请求书**中指定**摘要附图**
- [ ] 要求优先权的，已在请求书中写明在先申请的申请日、申请号与原受理机构

详见 `references/format.md` §1、§2、§4。

---

## §2 权利要求书

- [ ] 🔴 权利要求**从 1 起连续编号**，不跳号、不重号，编号前不冠"权利要求"字样
- [ ] 🔴 每一项权利要求**只有一个句号，且位于该项末尾**
- [ ] 🔴 权利要求中**没有插图**（可以有化学式、数学式、表格）
- [ ] 🔴 从属权利要求**只引用在前的权利要求**
- [ ] 🔴 多项从属权利要求**以择一方式**引用在前权项，且**不作为另一项多项从属的基础**
- [ ] 有且只有一项独立权利要求，且写在从属权利要求之前
- [ ] 独立权利要求**包含"其特征在于"**（或类似用语），前序部分 + 特征部分齐全
- [ ] 独立权利要求记载了解决技术问题的**全部必要技术特征**；非必要技术特征不要写进独权
- [ ] 从属权利要求用**附加技术特征**作进一步限定，不是重复独权
- [ ] 每一个"**所述 X**"都能在前文中找到对应的"X"（回指不悬空）
- [ ] 无含义不确定的用语：等、约、大约、类似物、厚、薄、高温、最佳、必要时、适当的
- [ ] 没有出现"如说明书……所述""如图……所示"这类引用语
- [ ] 科技术语与**说明书**一致
- [ ] 引用了附图标记的，标记**放在相应技术特征之后并置于括号内**
- [ ] 每一项权利要求都**以说明书为依据**（不是只在实施例里出现过一次就概括到整个类）
- [ ] 权利要求数目合理，无保护范围实质相同的同类权利要求

详见 `references/claims.md` §1～§5、§7。

## §3 说明书

- [ ] 🔴 五部分**按法定顺序**齐全：技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式
- [ ] 每一部分前面**写有标题**
- [ ] 无附图时，「附图说明」连同标题**可以整体省略**（发明专利；实用新型必须有附图）
- [ ] 说明书**文字部分没有插图**
- [ ] 技术领域写成"本发明涉及……技术领域"，不写成行业综述
- [ ] 背景技术写明了对理解、检索、审查有用的背景技术；有可能的引证了文件
- [ ] 背景技术**没有出现本发明的技术方案**，没有贬低他人或他人产品
- [ ] 发明内容三要素齐全：**所要解决的技术问题 + 技术方案 + 对照现有技术的有益效果**
- [ ] 有益效果**具体、可验证**（有指标/数据/对比对象），不是"效果良好"
- [ ] 技术方案与独立权利要求实质一致
- [ ] 具体实施方式**至少一个完整实施例**，本领域技术人员能据此重复实现
- [ ] 关键参数给了**范围端点 + 典型值 + 选取依据**
- [ ] 写了**可替代的变型**（材料/部件/步骤/参数区间）——这是日后修改的合法来源
- [ ] 🔴 说明书**充分公开**：未出现"只给目标不给手段""关键参数缺失""效果无法确认"
- [ ] 无商业性宣传用语（最佳、世界领先、填补空白、市场前景广阔……）
- [ ] 无"如权利要求……所述"这类引用语
- [ ] 涉及核苷酸/氨基酸序列的，序列表已按现行规定提交
- [ ] 全文术语、计量单位、参数符号统一

详见 `references/specification.md` §1～§8。

---

## §4 说明书摘要与摘要附图

- [ ] 🔴 摘要文字部分（**含标点**）不超过 **300 字**
- [ ] 摘要写明：名称 + 所属技术领域 + 所要解决的技术问题 + 技术方案要点 + 主要用途
- [ ] 摘要**不使用标题**，不使用商业性宣传用语
- [ ] 摘要中不出现"如权利要求……所述"这类引用语
- [ ] 摘要中的附图标记**加括号**
- [ ] 摘要附图已在请求书中指定，且缩小到 **4 cm × 6 cm** 仍可分辨
- [ ] 摘要与权利要求/说明书的表述一致（**摘要不能作为修改依据，也不能用于解释保护范围**——关键限定不要只写在摘要里）

详见 `references/format.md` §5、`references/drawings.md` §5。

---

## §5 说明书附图与附图标记

- [ ] 🔴 **说明书正文中出现的每一个附图标记，都在「附图说明」中列出**
- [ ] 图号"图1、图2……"连续、无跳号、无重号，标注在**图的正下方**
- [ ] 「附图说明」逐幅列出图名，与"说明书附图"中的图一一对应
- [ ] 附图说明中列出标记时**不加括号**；正文中提及标记时**加括号**
- [ ] 同一部件在全文使用**同一标记**；标记与部件名称一致
- [ ] 附图说明中列出但正文未使用的标记，已删除或已在正文补用
- [ ] 无照片（金相图／组织细胞图／电泳图谱除外）、无工程蓝图、无涂改
- [ ] 线条均匀、足够深；缩小到三分之二仍可分辨
- [ ] 图内文字使用中文，除必需词语外无其他注释
- [ ] 流程图、框图已作为附图提交，框内有必要文字或符号

详见 `references/drawings.md` §1～§6。

## §6 形式、程序与时限

- [ ] 纸张 A4（297×210 mm）；页边距上 25 / 左 25 / 右 15 / 下 15 mm
- [ ] 打字或印刷；字高不低于 3.5 mm；单面、纵向、黑色
- [ ] 各文件用阿拉伯数字**顺序编写页码**；附图作为说明书组成部分连续编页
- [ ] 🔴 已在**规定期限内**提出实质审查请求（发明专利）
- [ ] 要求优先权的，已在规定期限内提交声明与副本
- [ ] 收到审查意见通知书的，在**通知书指定的期限**内答复（可申请延长的情形见 `references/procedure.md`）
- [ ] 已核对最新收费标准与缴费期限
- [ ] 技术方案涉及需要保密审查的（向外国申请），已履行相应手续

详见 `references/procedure.md`。

## §7 提交前最后 5 分钟必须确认的事

按"代价从大到小"排序，**这五条每年都有人栽**：

1. 🔴 **权利要求编号连续 + 每项只有一个结尾句号 + 无插图** —— 三条最机械、也最常被漏掉的形式缺陷。
2. 🔴 **附图标记双向一致** —— 正文用了没在「附图说明」里列出，是形式审查阶段最典型的高频缺陷。
3. 🔴 **说明书五部分顺序正确且标题齐全** —— 少一个"发明内容"、把"附图说明"排到最后，都要补正。
4. 🔴 **独权的必要技术特征一个不少，非必要特征一个不多** —— 少了得不到保护，多了白白限缩范围且日后很难删（答复阶段的主动删除会扩大保护范围，属于不予接受的修改，见 `references/prosecution.md` §3）。
5. 🔴 **摘要 ≤300 字（含标点）** —— 超一个字都要改；注意摘要**不是**修改依据，别把关键内容只写在摘要里。
